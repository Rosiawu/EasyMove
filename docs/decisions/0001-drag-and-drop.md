# 拖放传输决策记录

## 背景

- 需求：文件应像 Windows 文件管理器一样通过拖放完成复制或移动。
- 验收：支持窗格、文件夹和系统外部文件拖入；正确区分同盘与跨盘；修饰键可强制指定操作。

## 现状

- 文件传输已经集中在主进程的 `fs:transfer`，支持进度、暂停、取消和失败清理。
- 渲染进程此前只有工具栏与键盘入口，没有拖放状态和目标反馈。

## 决策

- HTML 拖放只负责选择来源、识别目标和展示反馈，实际文件操作继续复用 `fs:transfer`。
- 主进程通过文件系统设备号判断默认复制或移动：设备号相同为移动，不同为复制。
- `Ctrl`/`Option` 强制复制，`Shift` 强制移动；具体文件夹行优先于窗格当前目录。
- 外部文件路径通过 Electron `webUtils.getPathForFile` 获取，不放宽渲染进程的 Node.js 权限。
- 拖出窗口时由主进程 `startDrag` 启动原生文件拖拽，并使用项目内置图标作为拖拽缩略图。

## 未采用的方案

- 仅按路径前缀判断磁盘：挂载点和符号链接可能导致误判。
- 在拖放逻辑中重新实现复制：会绕过进度、取消、冲突保护和失败清理。

## 风险与缓解

- 风险：把文件夹拖到自身内部。缓解：渲染层提前阻止，主进程传输层再次校验。
- 风险：跨盘行为与提示不一致。缓解：悬停使用快速估算，落下时由主进程设备号作最终判断。

## 回滚

- 回滚本次提交即可恢复 0.1.1；没有数据结构迁移，不需要额外清理。
