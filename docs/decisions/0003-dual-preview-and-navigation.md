# 双路预览与文件夹导航决策记录

## 背景

- 需求/问题：文件与文件夹需要同时支持悬停即时预览和单击后的右侧固定预览；Downloads、images 等可见文件夹存在双击后无法进入的问题。
- 目标与验收：悬停行内任意位置都能预览；单击任意项目都能在右侧看到预览或明确的元数据兜底；双击文件夹或点击预览窗格的“打开文件夹”都能进入真实路径。

## 现状（基于代码的事实）

- 原悬停入口只监听带 `data-preview-icon` 的缩略图节点，文件名、类型、日期与大小区域不会触发。
- 原单击处理在更新选择后立即执行 `renderPanes()`，第一次点击会替换整行 DOM，浏览器无法在同一节点上完成第二次点击和 `dblclick`。
- 原应用只有悬浮预览以及分栏/画廊内部预览，没有跨视图一致的右侧固定预览。

## 决策

- 悬停监听提升到 `.file-row`，400ms 后按需生成预览；在同一行内部移动不会重启计时。
- 列表与图标视图的单击只同步选择状态，不再重绘整个窗格，从根源上保留双击事件链。
- 在内容区右侧增加独立预览窗格；单击文件或文件夹后显示，关闭或切换当前窗格路径时收起。
- 图片显示真实缩略图，文本显示真实内容，文件夹显示封面与子项摘要；不支持生成视觉内容的格式仍显示类型、路径、时间和大小，保证任意项目都有可识别的预览结果。
- 悬停与固定预览共用 `ensureEntryPreview` 和结果归一化逻辑，避免重复请求以及主进程字段名和渲染字段名不一致。
- 右侧文件夹预览提供明确的“打开文件夹”按钮，文件提供“用系统应用打开”。
- 开始拖拽或进入剪切/移动流程时，统一关闭悬停预览和右侧固定预览，立即恢复完整窗格宽度；普通复制不会强制关闭固定预览。

## 备选方案（被拒绝的）

- 单击文件夹立即进入：会与“单击后在右侧预览文件夹”的需求冲突，也不符合桌面文件管理器的选择习惯。
- 继续在每次选择后整窗格重绘并手工合成双击：会让焦点、拖放和多选状态更脆弱，且没有解决根因。
- 把第二个文件窗格临时改成预览：会破坏 EasyMove 的双窗格复制/移动核心流程。

## 风险与缓解

- 风险：右侧固定预览会压缩文件窗格宽度。缓解：预览宽度限制为 250–310px，关闭后内容区立即恢复。
- 风险：用户快速切换选择时旧预览覆盖新预览。缓解：使用递增 token 校验当前路径，复用进行中的预览 Promise。
- 风险：超慢预览看起来无响应。缓解：超过 2 秒显示“建立索引中，请稍候”。
- 风险：拖拽时右侧预览压缩目标窗格、遮挡可放置区域。缓解：在设置拖拽数据后立即收起两类预览；所有移动入口在传输层再次兜底收起。

## 回滚方案

- 回滚本决策对应的渲染层 HTML、CSS 与事件处理改动即可；没有新增用户数据结构或磁盘迁移。
- 回滚后无需清理索引缓存或主题数据。
